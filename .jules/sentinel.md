
## 2024-05-18 - Command Injection in Shell Invocation via Environment Variables
**Vulnerability:** Invoking shell commands (like using `execSync`) and interpolating values derived from unsanitized environment variables (e.g., `process.env.GOOGLE_APPLICATION_CREDENTIALS` which stores a file path or other unsanitized strings) directly into the command string allows for command injection. In the codebase, this was used to extract a JSON field with a nested python shell invocation where the path variable (`saKeyPath`) was directly inserted inside the shell string, allowing for shell command injection or Python payload execution.
**Learning:** Even environment variables that point to standard file paths must be considered untrusted input if they are directly injected into a shell. Furthermore, attempting to use nested shell commands to read values from a file exposes execution risk and adds complexity. Whenever possible, rely on platform primitives (like Node.js `fs` and `JSON.parse` to read file content) instead of delegating simple data reading to another process via shell.
**Prevention:** Avoid `execSync` combined with shell string interpolation entirely. Always read and parse files natively via language libraries (e.g., `fs.readFileSync` and `JSON.parse`) instead of complex inlined scripts. If an external binary must be run, always use `execFileSync` or `spawnSync` passing arguments as a dedicated array (e.g., `["arg1", "arg2"]`) rather than a single string shell command, to prevent shell evaluation.
